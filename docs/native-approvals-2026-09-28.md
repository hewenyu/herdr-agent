# Jev 原生菜单自动处理（2026-09-28）

## 现场问题与变更授权

v0.3.18 的任务启动现场中，Codex 的目录信任已有成功工具回执；Claude 的完整屏幕包含 shell 启动命令回显，不符合原有精确目录菜单模板。pi 只回复了“已调用”文字，实际没有调用确认工具。用户手动确认后，规划于 07:32:30 UTC 完成，07:32:49 两位参与者的开场派发均恢复为 sent。停顿同时包含启动确认识别缺口和规划耗时，不能解释为 Jev 已处理权限菜单。

用户明确要求把后续阻塞、权限确认菜单改为“Jev 选择，程序执行”，并通过 PR 交付。这替代此前普通审批必须用户手选的产品约束；任务验收、用户业务取舍和任意终端执行不属于菜单确认。

## 配置与行为

`[jev] approvals_enabled = true` 是新默认值，只有 AI 启用且 Jev key 非空才生效。适用于所有受管任务模式，包括已有任务；不改变旧任务的调度模式。它把当前完整可见终端屏幕、任务要求、用户原文和修订发送给第三方 Jev。终端内容可能包含项目数据，应与本地配置凭据一样妥善管理。`ingress_enabled` 仍独立默认关闭；设置 Jev key 不会打开私聊分类。

设 `approvals_enabled = false` 并重启后，普通审批保留手动卡片选择，启动目录信任保留旧的 pi 受限确认流程。自动审批不修改 Bypass、不自动验收、不向普通 pi 会话增加 shell 或任意终端工具。

新流程读取 herdr 的完整 `visible` 屏幕，不从固定目录信任文案判断按哪个键。程序生成受支持的数字、y/n、导航、确认和取消候选；Jev 选择一个候选，失败或低置信度时 pi 只能调用 `approval_decide` 选择同一候选集。未调用工具的文字答复没有效果。未编号菜单逐次导航、逐次观察；数字键仅按一次，不能隐式扩展为“上移 + Enter”。

菜单文案、位置、启动回显和选中项改变不要求更新目录模板。前提仍是 herdr 能报告阻塞状态、提供可读完整文本，且界面支持已有按键。无法读出的界面、未知按键、账号密码、验证码和缺失的用户业务决定选择 `wait_user`，不能承诺任意未来交互都自动完成。

## 执行与恢复

1. 选择前、执行前校验持久任务、参与者、暂停/关闭状态、用户修订、授权目录和执行位置；按键前核验 terminal、session、stateSeq 及完整屏幕指纹。已认证的生命周期、interrupt、参与者增删请求和用户新安排在等待任务锁前登记临时阻止标识，避免用户暂停被模型调用占锁挡住；原生最后一次读屏后同步检查该标识和当前授权。旧 TaskService 停止或断线替换时也撤销其审批执行权限。已持久入队且与任务有关的飞书 task/group 事件、所有者消息或卡片，也会在 inbox 获得任务锁之前立即阻止自动输入；处理完成后，接收事件的版本参与决定身份，普通远端更新不会永久冻结未执行的决定。
2. 使用现有 `Approvals.create/answer` 和 consumed nonce，自动与人工操作共用同一执行链。同一执行位置串行写入，导航后的旧卡片失效。
3. 每次只发送一个受支持按键，回读新屏幕与执行器身份。只有可识别的菜单选项/选中项变化或执行器恢复运行才确认该步；屏幕上的日志、时间或 spinner 变化不构成确认。未编号菜单只以光标所指选项变化作为阻塞现场的证据；无法提取选择状态时保持 unknown。后续菜单即使 stateSeq 不变，有可核验选择变化也可重新选择。
4. 选择前保存记录，按键前保存 executing。未知效果或执行中崩溃冻结该执行位置的自动写入，不能通过重启、换画面或状态号重发。明确 stale_guard 或任务作用域已变化且未执行的拒绝可以重新观察；用户显式恢复通过既有 task_pause_revision 更新输入版本。
5. 未产生选择或 stale_guard 明确拒绝写入后冷却 30 秒，同一执行位置与用户输入在没有已确认审批进展时最多选择三次，次数与冷却持久保存。屏幕指纹、nonce、stateSeq、选项内倒计时、不可解析菜单变化或无害远端通知都不会重置预算。事件接收版本只用于执行前拒绝旧决定，单独保存的用户语义版本用于重试与导航循环判断。自动和人工通过同一审批链确认成功后开启新的重试阶段，用户更新要求也可以重新评估，后续权限不累计成任务级上限。同一 stateSeq 的相同屏幕在相同用户输入下成功操作两次后再次出现，转人工检查导航循环；正常运行后新一轮相同权限不会累计成旧导航循环。这不限制任务讨论轮数，也不自动收尾。

本地 SQLite 的 `automatic_approval_decisions` 保存屏幕快照、用户输入版本、合法候选、Jev 分布、最终选择来源、nonce 和执行结果。普通运行日志只记录 `approval.automatic_selected`、`approval.automatic_completed`、`approval.automatic_failed` 的标识、来源、置信度和错误码，不打印屏幕或 key。

真实模型探针：

```sh
node --import tsx scripts/live/native-approval-probe.ts result.json
node --import tsx scripts/live/native-approval-probe.ts result-with-pi.json --with-pi
```

探针只发送合成屏幕，完全禁止原生操作，也不发送飞书消息。默认只测 Jev，`--with-pi` 使用本地配置的真实 pi 作为受限后备选择器。保留 [Jev 单独记录](native-approval-jev-probe-2026-09-28.json) 中的低置信度结果，不调低门槛伪造成功；[Jev + pi 记录](native-approval-jev-pi-probe-2026-09-28.json) 单独记录实际来源。

实际结果：Jev 单独测试三项高置信度匹配，另两项低置信度、未生成可执行决定。启用真实 pi 的第二次运行五项均匹配，其中两项由 Jev 接受、三项由受限 pi 选择；两个模型调用之间仍可能有概率波动。新增 [y/N 合成记录](native-approval-letter-probe-2026-09-28.json) 中 Jev 选择 key:y，置信度 0.81。这些探针证明选择器及回退协议，不证明原生按键或完整飞书任务已现场验收。
