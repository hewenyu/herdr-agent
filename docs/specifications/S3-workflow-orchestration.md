## 1. 交付范围

建立可持续推进的 workflow：状态层、讨论/新需求/小 Bug 三套模板、版本化状态块、仓库外看板、报告合同、Jev 适配器、受限 pi 后备和可回放决策日志。同步完成阶段门禁、跨任务目录冲突检查及既有派发恢复链适配。

不在 S3 开启私聊 Jev 分类或 myrix 命令执行；不设影子上线阶段；不恢复轮数/决策数/累计时长预算；不新增 dispatch_intents、租约或独立状态版本计数器。

## 2. 必须保留的接口约束

- workflow 作为每任务新 mode，配置 Jev key 后的新任务默认使用；已有模式与显式选择不变，任务和 AI 总开关继续生效。
- 沿用 `revision()`、`userRevision` 和 superseded。仅 workflow 增加计划版本、阶段输入，旧任务 hash 不变。
- 选择写入 `OrchestrationEvent.decision`，派发写入现有 `dispatches`，仍由 `tasks().send` 执行并由 `reconcileDispatches()` 恢复。
- workflow 后备 pi 只能调用选择候选的 `orchestration_decide`。旧 model 的业务工具路径保持原语义。
- `processTask()` 按本阶段已派出的活动集合等待；`send.ts` 非讨论任务串行约束保持原样。
- `participantPromptCandidates()` 精确保留旧模板；新协议不得破坏历史投递回读。
- 新代码进入 `src/orchestration/`；不把已有 845 行 orchestrator 扩成超过 1000 行的实现集中点。

## 3. 数据与协议合同

计划记录包括身份、不可变版本、模板类型、目标、约束引用、阶段、节点依赖、角色绑定、问题及交付合同。bugfix 映射现有 development 任务类型。

状态块保存协议版本、节点、委派及输入版本引用、摘要、问题、产物、证据、阻塞。块内容是参与者报告，不是用户授权；先确认输出归属，再解析和归并。非法块保留原文并请求补充，不能伪造完成。

决策日志至少包含：事件及 revision、计划/模板版本、快照引用、候选全集、规则结论、Jev 调用状态与分布、模型与门槛版本、pi 后备原因和结果、最终来源/候选、派发回执关联。skipped、timeout、invalid、low-confidence 分别记录，不伪造分布或解释。

看板放在 `stateDir/tasks/<id>/board/`，以现有 `--add-dir` 挂载。数据库记录是权威事实，看板是可重建投影；正式报告保留不可变版本和哈希。不修改用户仓库及 Git 排除文件。

报告来源标签至少区分“参与者自述”“agent 复核”“配置命令执行记录”“未运行”。S3 尚未实现 S4 执行器时，不能生成 myrix 命令验证证据。

## 5. 验收矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| S3-A01 | key 有/无、显式策略、历史任务 | 只有符合前置条件的新任务默认 workflow；旧模式及验收设置不变 |
| S3-A02 | 三类用户需求 | 模板按目的推进；小 Bug 默认四节点，合并针对性验证/独立评审；复杂化时重规划；讨论不越权开发 |
| S3-A03 | 超出旧 maxRounds/maxDecisions/maxMinutes | 有进展可继续，不因旧预算截断 |
| S3-A04 | 非空 open 连续 N 轮不变 | 只产生用户裁决请求；重试/重启不重复计轮；不自动 deliver |
| S3-A05 | 用户改需求或取消时 Jev 返回 | 原选择失效，未发生的新派发被阻止，已有副作用可追溯 |
| S3-A06 | Jev 正常、超时、非法响应、低置信度 | 同一合法候选回退受限 pi，最终来源与原因可查；pi 失败不循环重问 |
| S3-A07 | 规则已决定或候选无工作动作 | 不强选工作、不伪造 Jev 分布，保存等待/重规划原因 |
| S3-A08 | 初始未派发参与者和独立开场 | 未派发者不阻塞，讨论开场可批量派发，批次结束后再交叉回应 |
| S3-A09 | 非讨论任务及局部阻塞 | 原串行约束保留；未结束/blocked 不计完成，阶段拆分需明确记录 |
| S3-A10 | 两任务通过符号链接或父子目录写入 | 冲突派发不并行；未知旧写者不被超时抢占；不使用租约 |
| S3-A11 | dispatch 前后各崩溃窗口 | 复用原选择、operationId 和回执，不重复外部效果 |
| S3-A12 | 迟到/重复输出及非法状态块 | 原文保留，错误输出不推进新节点，不伪造证据 |
| S3-A13 | 当前与旧讨论 prompt 回执 | 新协议任务可解析，历史任务精确回读成功 |
| S3-A14 | 仓库外看板 | agent 能读；用户仓库和 .git/info/exclude 无辅助改动；看板不产生授权 |
| S3-A15 | 缺产物、证据过期或报告不完整 | deliver 被合同拒绝，单个 outputId 不足以交付 |
| S3-A16 | 正文成功卡片失败或发送未知 | 只恢复确定未送达部分，不重复正文；未知保持待核验 |
| S3-A17 | 报告送达但用户未验收 | 不自动关闭任务、执行器或群 |
| S3-A18 | 离线回放 | 可还原三种来源的选择过程，不调用任何业务写操作 |

## 6. 完成标准

实现任务、对应自动检查及真实链路证据齐全后才标记完成。`npm run check` 包括行数、类型、lint 和测试；执行构建，并按项目现有现场矩阵记录真实任务验证。受限环境或未运行检查分别列出，不能用 fixture 结果冒充 Jev 或飞书实测。

S3 通过后进入 S4；在 S4 边界配置、默认值和文档同步完成前不作为完整新版发布。效果评估可以离线进行，不要求建立第二个有执行权的影子调度器。
