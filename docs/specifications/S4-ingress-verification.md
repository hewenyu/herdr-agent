## 1. 边界变更确认方案

### B1：AI 模式采用“规则 → Jev → LLM”

已确认的新原则：程序负责确定性协议和安全约束；明确开启私聊分类时，Jev 只选择 intent/project；满足门槛且参数完整的建任务请求由程序执行；其他对话和业务请求交给 pi。任务内 workflow 的低置信度后备则只用受限 orchestration_decide，两种 pi 路径分别定义。

| 项目 | 确认内容 |
| --- | --- |
| 变更前 | AI 普通对话与工具调用均由 pi 模型决定，exact /clear 直接执行 |
| 变更后 | 在 opt-in 入口允许 Jev 分类结果驱动确定性 tasks.create |
| 开关 | 新增 `[jev].ingress_enabled = false`；配置 key 不开启该开关 |
| 输入外发 | 开启后，规则未处理的适用私聊原文及必要项目候选会发送给 Jev；不默认发送全历史、仓库或附件 |
| 创建字段 | requirements 保留用户原文，title 确定性截断，project 必须是允许的目录项；其余字段必须有明确模板/项目默认，否则交给 pi |
| 限制 | 不由 Jev 抽取任意文本、生成新项目、提升授权或绕过去重 |
| 失败与关闭 | 超时、低置信度、不确定项目或参数不足回原 pi；开关关闭不发私聊 Jev 分类请求 |
| 兼容 | 任务群、历史任务、exact /clear、身份与回执边界保持原规则 |

README 中英文、配置示例和现行架构原则须同一改动同步更新。表述应明确“默认关闭时普通 AI 文本仍由 pi 处理”，避免新旧原则互相矛盾。历史审计保留当时事实，仅添加指向新版本的说明（确有需要时）。

### B2：myrix 执行项目显式配置的 verify

已确认的新边界：myrix 可以运行本地项目所有者显式配置的验证命令；pi runtime 仍没有通用 coding/shell 工具，模型不能提供任意命令字符串或改变 cwd。

| 项目 | 确认内容 |
| --- | --- |
| 变更前 | myrix 委派 coding agent 执行项目工作，runtime 只注入业务工具 |
| 变更后 | 新验证执行器读取项目配置 verify 命令列表并记录进程证据 |
| 开启方式 | 仅项目显式 `verify = ["npm run check"]`；缺失/空数组均不执行 |
| 可调用范围 | 调度器只引用配置命令身份，不能把用户或模型文本插成 shell 参数 |
| 执行位置 | 固定任务实际主 cwd，包括 worktree；不能由模型选择其他目录 |
| 运行约束 | 有限单命令超时、取消与进程退出核对、目录冲突协调；不设置任务总时长配额 |
| 记录 | 命令、配置版本、cwd、产物版本、stdout/stderr、退出码/信号及超时结果 |
| 无配置 | 委派非实现者 agent 独立重跑，报告标“agent 复核”；无法运行标“未运行” |
| 事实边界 | cwd 限制不是 OS 沙箱；命令有本机权限；退出码 0 不等于所有需求验收通过 |
| 关闭方式 | 清空 verify 阻止新运行；已启动的运行需明确取消/退出核对，不声称配置移除自动撤销效果 |

配置命令属于本地项目设置，不接受聊天或模型静默改写。项目目录已有的 TOML 初始种子与 SQLite 持久目录机制都需支持该字段；验证运行绑定当时配置，配置变化使尚未启动的旧候选重新校验。

两项边界均已由用户接受，已实现并同步到中英文 README 和配置示例。本机只配置 Jev key；入口分类仍关闭，没有为用户已有项目添加 verify。隔离测试项目的命令执行及恢复有自动证据；发布与真实飞书链路不在本次已执行范围。

## 2. 已实现的配置合同

当前配置加载器支持以下字段：

```toml
[jev]
api_key = "" # 仅本机私有配置，不能把真实密钥放入仓库
ingress_enabled = false

# 既有项目种子示例；SQLite 已有目录项时须走项目配置更新路径。
[tasks.projects.example]
directories = ["~/code/example"]
agent = "codex"
verify = ["npm run check"]
```

Jev 请求和验证命令均设有限的单操作超时，默认值及允许范围在实现和测试中固定。它们用于恢复卡住的调用，不恢复已废弃的任务预算。API key 不进入决策快照、报告、日志或 Web 明文回读。

验证命令采用单调时钟，从实际尝试启动子进程之前开始计时；启动前日志准备与最终授权检查不计入。同步启动工作消耗预算，计时器只等待剩余时间；关闭事件被观察时若期限已过，即使退出码为 0 也不能判为通过。这是保守的观察时刻判定，不声称知道子进程的精确完成时刻。退出未确认仍为 unknown；预算耗尽后晚到的取消不能把结果降为可安全重试的 cancelled。

本次本地准备：用户提供的 Jev key 已存入当前默认状态目录 `~/.herdr-agent/config.toml` 的 `[jev].api_key`，文件权限 `0600`，`ingress_enabled = false`。配置加载器已消费该节；已通过一次真实合成 Jev Choice 请求验证 key 与 API 合同。此记录只说明本机准备状态，不是部署默认路径承诺，也不包含密钥值。

## 4. 验收矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| S4-A01 | 已配置 key 但入口关闭 | 新任务可默认 workflow；普通私聊不调用 Jev 入口分类 |
| S4-A02 | 开启入口，高置信度 intent/project | 创建参数来自原文和合法默认；否定约束保留，创建回执可核验 |
| S4-A03 | 分类低置信度、失败或项目不确定 | 回退原 pi，不猜项目、不创建空 title/requirements |
| S4-A04 | 多参与者、引用上下文、非文本资源 | 无法完整确定参数时交给 pi，不忽略原要求建简化任务 |
| S4-A05 | 重投消息或分类后进程崩溃 | 复用路由和原创建来源，不能创建第二个任务 |
| S4-A06 | exact /clear、任务群和未授权用户 | 保持原规则，不误走新分类 |
| S4-A07 | 无 verify 或空 verify | myrix 不起命令；独立 agent 复核或准确标未运行 |
| S4-A08 | 显式 verify 正常成功/失败 | 固定任务 cwd，保存原 stdout、stderr、退出码和版本 |
| S4-A09 | 模型提交未配置命令或其他 cwd | 拒绝，不扩展 runtime 工具权限 |
| S4-A10 | 超时、取消、执行中重启 | 不伪造退出；安全取消后恢复可重新选择并保留原记录，重放原候选不重跑；失败、超时和未知结果不自动重跑 |
| S4-A11 | 同目录写入及验证后的代码变化 | 目录门禁生效，受影响证据失效并阻止过早交付 |
| S4-A12 | verify 配置更新和重启 | SQLite 设置不被 TOML 种子覆盖；新运行重校验配置 |
| S4-A13 | agent 复核、自述、配置命令和用户禁止验证的证据混合 | 报告逐项明确来源，无配置时不标 myrix 已验证；用户禁止验证时不执行命令、保留独立只读复核并明确标未运行 |
| S4-A14 | README、配置、现行设计交叉检查 | 路由和命令边界一致，默认关闭及隐私影响明示 |
| S4-A15 | 日志、报告、版本库和配置回读 | 不含真实 API key；私有配置权限正确 |

## 5. 发布要求

自动检查、构建与真实飞书入口的分类/建任务/报告链路分开记录。真实 Jev 测试使用本机私有配置，执行真实 verify 的场景选择已明确配置的隔离测试项目，保留 stdout 与退出证据。未测的语言、模型或平台如实列出。
