# 本地服务日志

`myrix`、`myrix serve` 和 `myrix configure` 默认把结构化运行日志追加到
`<stateDir>/log/myrix.log`。新安装默认使用 `~/.myrix`；已有 `~/.herdr-agent` 的安装继续使用该目录。
`--state-dir` 以指定目录为准。启动时终端显示 Web 地址和日志路径；
使用 `--json` 时日志位置通过 `log_ready` 事件输出。飞书连接和订阅完成后，终端再显示一条就绪提示。
无需额外使用 `tee`。

日志逐行保存 JSON，包括飞书连接、消息入队与处理、pi 调用、原生审批和任务调度已有的诊断事件。
每次启动记录 `service.started`、运行版本、Git 提交和 PID，正常退出记录 `service.stopped`。
仅保存诊断字段；沿用日志脱敏，不保存 API key、模型完整 prompt、消息正文或完整响应对象。
业务内容与原生对话仍由已有任务状态和 session 记录保存。

当前非空文件加上下一条记录将超过 10 MiB 时，在写入前轮转，最多保留 `myrix.log.1` 至 `myrix.log.5`，
其中 `.1` 最近；单条记录保持完整，因此极大的单条记录可以超过此大小。
重启追加现有文件，不清空历史。日志文件权限为 `0600`，新建日志目录权限为 `0700`。

服务取得状态锁后才打开日志，第二个服务启动失败不会改动已有日志。
`help`、`version`、`status`、`doctor` 等只读命令不创建日志文件。
日志目录不可写、磁盘写入或轮转失败时，会在终端明确提示并退回控制台日志；
不会因此把已完成的任务动作当成失败重新执行。

审查运行状态时，可提供问题发生的大概时间和任务名称，并读取当前日志及相邻的轮转文件。
例如沿用旧状态目录的安装可实时查看：

```bash
tail -F "$HOME/.herdr-agent/log/myrix.log"
```
