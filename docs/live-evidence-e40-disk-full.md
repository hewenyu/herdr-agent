## 测试脚本失败与清理

第一次准备时，hdiutil 返回 `/private/var` 挂载点，脚本却以未经规范化的 `/var` 比较，未识别到新卷。随后清理尝试移除仍挂载的目录，返回 `Resource busy`；此时尚未启动产品或填充磁盘。已按 hdiutil 实际映像与设备回读确认后卸载、删除专用临时目录，原始记录 `e40-enospc-attempt1.json` 保留。脚本随后改用规范化路径，并在删除目录前核验卷已卸载。

第二次已完成上述产品写入失败、重试和重启检查，最后普通 Python SQLite `mode=ro` 完整性探针返回 `unable to open database file`，连接未在异常路径及时关闭，首次卸载因忙失败。该记录 `e40-enospc.json` 保持 ERROR，没有覆盖成全脚本成功。

后续独立检查在该临时库用 `mode=rw` 读取完整性为 ok，留下空 WAL/SHM；“必须无 sidecar”这一过严的脚本前置断言也保留说明。确认两个测试进程退出、无打开句柄及 WAL 长度为 0 后，用规范化路径和 `mode=ro&immutable=1` 对静止数据库完成只读完整性检查，数据库 hash 未变。最终成功卸载本轮实际设备，并删除专用映像、复制的二进制、临时配置和测试填充文件；生产文件未删除。

最终评估及 16 项检查见 `.cache/live/e40-enospc-completed.json`；准备脚本为 `.cache/e40-enospc.py`。这些本地证据保留测试工具失败和后续核验，不把工具假设错误当成产品缺陷，也不称整条初始脚本无错误运行。
