# 自然语言对话与记忆

## 本分支目标

分支 `fix/conversation-context-compaction` 完成应用私聊与任务群的连续自然语言沟通、上下文自动压缩及可替换的本地记忆机制，通过测试和 PR 交付。

- 应用私聊负责需求沟通、澄清、新建项目/任务、任务总览；具体任务的讨论、反馈和验收在绑定的任务群继续。
- 普通问题、建议、项目名称和文件名使用自然语言回复。保留助手提出的问题与用户的回答，使“就叫这个”“按刚才的方案”有可追溯的上下文。
- 操作回执和任务进度来自实际工具结果。历史对话、记忆和编码 agent 的自述不能证明当前任务状态，也不构成新的操作授权。
- 默认上下文压缩阈值为 50,000 tokens，包含系统提示、任务快照、对话和工具定义。达到阈值自动摘要旧问答，保留当前输入、近期对话、已确认要求、否定约束和未决问题。
- memory provider 是摘要存储与召回接口，与摘要使用的模型分离。默认本地文件，可配置外部 HTTP 服务，并允许不同飞书用户使用各自的 provider；近期问答原文、检查点、归档和回执继续保存在本地。
- 记忆按用户、聊天和任务绑定隔离。本地持久化后可重启续聊；压缩不删除操作去重凭据，不重复执行任务操作。
- 摘要调用不提供任务工具。摘要或记忆服务失败时保留原对话、明确反馈；不以静默删除约束的方式换取请求成功。

## 验收范围

覆盖首次创建缺项目名的澄清、短回答承接、应用与任务群隔离、重启恢复、达到阈值后的连续对话、摘要失败恢复、provider 用户覆盖与错误脱敏，以及压缩前后的任务操作幂等。两种模型协议均保留支持。

本轮不自动合并或发布 tag，不更改正在运行的服务，也不通过测试创建真实飞书任务。

## 配置

现有配置无需新增字段即可使用本地记忆。修改配置后重启服务：

```toml
[ai]
context_tokens = 50000

[memory]
provider = "file"
timeout = "10s"

# 可选：只有这个飞书用户使用自己的记忆服务，其余用户仍使用本地文件。
[memory.users."ou_REPLACE_WITH_USER_ID"]
provider = "http"
base_url = "https://memory.example.com/herdr"
api_key = "REPLACE_WITH_MEMORY_SERVICE_KEY"
timeout = "10s"
```

`memory` 配置指定摘要存储与召回服务；摘要仍使用 `[ai]` 的模型、协议和密钥。用户覆盖项是完整、独立的配置，不继承全局 HTTP 地址或密钥；遗漏字段使用独立默认值 `file`、空地址/密钥和 `10s`。所有记忆密钥仅从 TOML 读取。HTTP 仅允许回环地址；远端必须 HTTPS 并配置密钥。存储请求超时必须大于零且不超过 `2m`，默认 `10s`。

`context_tokens` 是输入上下文阈值，默认 `50000`、允许 `16384..1048576`，包含系统提示、任务快照、对话、工具 schema 和当轮工具结果。按 UTF-8/JSON 字节及结构开销保守估算，不是供应商精确计费 token 数。输出上限另为 `4096` tokens，模型实际窗口必须能容纳输入阈值与输出。达到或超过阈值会压缩旧问答，通常保留最后四轮；近期消息过长时进一步减少保留轮数，把未决问题纳入摘要，当前用户消息始终完整保留。单条输入或固定提示本身放不进预算时明确报错，不截断要求。

使用已锁定 Eino 的 `adk/middlewares/summarization`，通过 `NewTyped`、`Summarize` 和 `BeforeModelRewriteState` 接入历史摘要与工具循环中的自动摘要。项目的策略层负责保留近期问答、分块处理过长历史、校验摘要长度和完成状态、对接 provider，并保存重启所需的会话检查点。模型明确标记为不完整或截断的输出不能成为成功摘要；失败时保留原历史。摘要模型没有任务工具；工具循环压缩继续原 runner，不重新执行先前工具。

## 本地数据与恢复

- `~/.herdr-agent/conversations/` 保存近期原始问答、摘要检查点及消息回执，文件权限 0600。普通追问和建议进入后续对话；历史执行回执由最新任务快照替代。
- `~/.herdr-agent/memory/` 是默认文件 provider 的摘要库，只保存摘要与 revision；以可信用户、聊天及任务绑定组成 scope，路径使用 scope 的哈希值。
- `conversations/archive/` 保留每次压缩移出的问答原文和前一份摘要，便于本地核对或恢复。归档不会自动当作当前指令重新执行。
- `assistant-operations.json` 继续保存任务操作幂等记录，不随对话压缩删除。

外部 provider 只接收相应 scope 的压缩摘要，不接管本地问答原文、任务、回执或鉴权状态。需要模型处理的每轮对话先召回该 scope 的摘要；本地已有对话检查点时，以本地摘要和完整近期问答恢复一致状态，必要时修复未同步的 provider。只有全新的本地会话才从召回摘要初始化。provider 已存入而本地写入失败时，不因存储不一致而重放任务操作。切换 provider 后，下一轮使用记忆的对话会将既有本地检查点中的摘要同步到新存储；不会迁移问答原文，也不会自动复制或删除旧服务中的数据。

摘要是有损归纳。原文归档提供核对依据，关键需求和未决问题由摘要指令优先保留；模型摘要不构成绝对无损保证。任务的当前状态仍查询工具。无工具回复中的明显虚构执行声明有防御性检查，但普通自然语言不依赖固定句首白名单。

## HTTP provider 协议

外部记忆服务需实现本项目的 HTTP 协议；其他记忆系统可实现此协议的适配服务，或在 Go 中实现 `internal/memory.Provider` 接口。当前支持精确 scope 摘要召回，不提供跨任务的向量搜索。

对 `base_url` 追加下表路径，以 JSON 发起 POST。配置非空 key 时发送 `Authorization: Bearer <key>`。不会跟随重定向，不自动重试请求。请求/响应限制 1 MiB。

| 路径 | 请求 | 成功响应 |
| --- | --- | --- |
| `/recall` | `{"scope":{"owner_id":"ou_x","chat_id":"oc_y","task_id":"t_z"}}` | 200：`{"summary":"历史摘要","revision":"不透明版本标记"}`；204 或 404 表示没有记忆 |
| `/store` | `{"scope":{...},"entry":{"summary":"历史摘要","revision":"..."}}` | 200、201 或 204 |
| `/forget` | `{"scope":{...}}` | 200、204 或 404 |

私聊的 `task_id` 省略；群聊使用服务端绑定的任务 ID。scope 始终由已认证飞书事件提供，模型不能选择另一个用户或群。服务必须按完整 scope 隔离数据。`revision` 是一致性检查用的元数据，不是并发 CAS 协议。当前由一个持有服务实例锁的进程更新同一会话。

provider 调用失败时返回不含地址响应体或凭据的固定提示，保留本地记录，阻止该轮新的任务操作。恢复服务后可重新发送完整要求。纯任务状态查询仍直接读任务记录，不依赖记忆服务。
