## 本轮行为

### 普通讨论的规划

首轮采用固定图：顺序开场 → 文档写作（若授权）→ 独立评审 → 各方认可（若要求）→ 报告。Jev 直接选择以下模式：

- 仅讨论和报告。
- 将设计写入默认 `docs/DESIGN.md`，再独立评审。
- 写入默认文档，并要求每位参与者认可同一版最终文档。
- 请 pi 补齐必要参数，例如用户指定了不同文档路径。

普通首轮的 pi 工具不提供自定义节点图和验证策略参数，运行时也拒绝绕过。复杂重规划仍可调整结构；已有共同认可合同不会因 pi 省略字段而消失。文档节点先由程序生成，再应用任务说明，避免覆盖不存在的节点或创建重复“写作”节点。

用户后来明确取消文档或共同认可要求时，规划器可提交显式撤销，必须引用最新且重新核验绑定的真实任务输入，再由 Jev 核对撤销范围。旧原文、查询消息、模型省略字段、低置信度或失败都不能自行降低门槛。核验结果与计划中的授权引用持久保留。

每次规划提交记录结构、耗时、输入哈希、失败字段/节点和错误。同一内容再次产生相同错误时终止该次规划并进入待处理状态。没有新增业务轮数上限，也不会强制综合或自动验收。

### 用户来源

新 workflow 的 requirements 由当前真实用户原文和显式引用的历史用户原文组成。pi 提交的概括留在 `task_creation_summaries` 审计，不能成为附加授权或限制。

`request_history` 只提供当前身份、会话及群绑定下已处理的真实用户消息；`contextMessageIds` 必须引用这些记录，程序按原入站顺序保存。助手答复、其他会话和未处理消息不能被引用为授权。历史消息是否与本轮相关仍由入口模型依据用户指代判断；消息 ID 校验不等于语义相关性证明。

任务查询产生的 read/control 来源仍保留审计，但不会进入 v3 的规划原文和参与者任务书。这样私聊查询旧任务时提到的新项目要求不会变成旧任务约束；同一消息随后确实执行任务输入并升级为 input 后，才进入规划与交接。旧版行为不变。

新 v3 的“不运行验证”只能引用完整用户原文，不能用任务摘要或截取的片段代替。旧版已有记录保留兼容读取。

### 重启与续接

用户明确要求重新拉起时，入口调用 `participants_restart`。关闭旧实例和替换实例使用稳定操作 ID；重试复用已完成回执，不重复创建。恢复材料放在 `stateDir/tasks/<id>/recovery/`，记录已有材料、旧实例和未知输入，要求新实例先核对文件再继续。

每位参与者的历史在关闭前保存检查点；中途崩溃后的重试不重新读取已关闭实例来覆盖旧证据。新消息明确要求续接同一批目标时，持久关联到原重启请求；同消息重放、服务重建后继续均复用同一结果。新实例显式挂载恢复材料目录。成功替换后，旧 unknown 审计也不会继续阻止当前任务的 retry 和收尾错误清理。

旧 unknown 操作的 state、fingerprint、dispatch 原记录不变，另记与这次显式重启的关联。只有目标参与者的旧输入可退出当前调度门禁；无法归属的外部未知操作仍阻塞。明确未执行的关闭可重试，未知关闭不能盲目重发。完成事件在关闭期间到达时，不提交新的替代实例。

旧作者身份继承到替代参与者，不能通过重启把作者伪装成独立评审者。旧规划和报告按现有 revision 失效，后续只安排当前有效参与者。

### 完成事件与输入边界

相关任务、群及用户消息一旦持久入队，新的调度输入暂缓，不必等待事件处理器拿到任务锁。已处理事件也会使正在计算的旧决策失效。任务/群远端核查失败时，保持等待。

输入守卫覆盖业务发送、原生现场读取、socket 连接以及 `socket.write` 前。日志分别记录 `input.write_started`、`input.acknowledged` 和 `input.readback_completed`，不记录输入正文或秘密。已经越过写入边界的输入无法撤回，仍按真实回执处理。

任务完成后的既有冻结报告恢复保留独立合同校验，不因已经处理过的验收消息而永久失效；该例外不允许新业务派发。

### 双方共同认可

只有要求各方认可的文档模式启用此门禁。确认节点绑定具体参与者，每人逐一读取最终文件和前序材料，并提交对前序 outputId 的具体回应。机器回执仍写独立文件；原生聊天仅短句交接和材料位置。

认可绑定本人输出、当前节点、工作区版本和每份文档的实际 SHA-256。任一未确认、明确拒绝、空回应、错误哈希或未处理分歧都会阻止交付。报告只引用当前最新产物证据，并在冻结和真正交付前读取文件核验；被 Git 忽略的文档修改也不能复用旧认可。报告嵌入的文件内容必须对应认可时的哈希。

这证明程序取得了双方对同版文件的明确表态，不证明模型在语义上完全理解文档；也不代替用户验收。普通允许保留分歧的讨论不自动增加共同认可条件。
