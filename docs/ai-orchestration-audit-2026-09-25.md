# 持续多 Agent 调度审计与修复

审计基线：`master@492d4edf190ea569595263e7a6e5de2b828df321`。本次分支从该主分支独立创建，不以未合并 PR #48 作为基线。

## 本轮诉求

用户需要一次提交目标后，由 AI 根据实际结果持续安排多 Agent 讨论、执行、复核、修订和最终交付。执行层仍属于 herdr：pi 不增加 shell、文件编辑或独立 Claude/Codex 进程管理能力。

当前系统与用户期望的主要差距不是更多固定流程，而是执行结果没有唤醒可继续行动的调度模型。轮流发言不能代替目标驱动的协作；创建任务、Agent 空闲和发出通知也不能作为交付完成的证据。

## 原始问题与修复方向

| 原始缺口 | 本次行为 |
| --- | --- |
| 开发/评审/测试任务只向第一位参与者自动投递，后台结果只生成只读通知 | 新建 AI 任务使用模型调度；参与者就绪和真实最终输出触发持久化决策，模型自行选择下一位或再次安排同一位 |
| 讨论只是固定轮转，没有整合交付阶段 | 模型判断是否需要继续讨论、补证据或返工；综合业务结果先委托参与者整合，最终交付引用真实参与者输出 |
| assistant 文本可能仍处于工作中，过早交棒 | 原生状态已结束且最终输出已落盘后才唤醒后续调度；同次读取的多个候选保留最后结果 |
| 下一位在审批、启动或工作时丢失待接力事项 | 保留待处理事件，下一次核对现场后继续；普通审批仍等用户 |
| 后续消息没有独立投递标识，丢确认后只能永久等待 | 每次投递先保存完整正文和唯一标识，再调用 herdr；通过原生 user 记录或已提交回执恢复，不盲目重发 |
| 模型暂时失败、进程中断、回复部分发送后请求永久失败 | 持久检查点和有界恢复沿用原消息与回执；已经确认的操作不重复，未知写操作保留待核验 |
| AI 开启后失败只有内部状态，用户看到沉默 | 重试耗尽或结果不明时提供操作中断的事实反馈，不把错误生成成业务成功答复 |
| 主私聊新增参与者没有关联本轮原文，已有任务不触发新决策 | 新增成功与幂等恢复均关联经过身份核验的用户请求；新参与者就绪后按用户修订继续调度，无效或回滚操作不登记修订 |
| 中断通知明确未发出后永久停在已尝试状态 | 确定未发送时持久化退避并恢复待发送，重启和并发轮询仍只发送一次；未知送达保持不重发 |
| 中间输出的飞书确认丢失会冻结原生观察和后续调度 | 原生产出先独立落盘，模型仍可读取并继续任务；未知消息保留原回执，不自动重发；最终通知与输出重试并发或落盘中断时，只凭同一消息的成功回执恢复状态 |
| 飞书请求/响应体或启动身份查询悬挂 | 整体期限覆盖请求和响应读取，取消时区分未开始与已提交；停止旧启动不让迟到结果接管新连接 |
| 模型转述可能丢失原文约束 | 绑定经过身份核验的用户原文，原文与 pi 分派摘要分别保存和传递 |

## 调度职责和兼容性

AI 的 `task_create` 默认使用 `orchestration.mode=model`；用户明确选择 `discussion.mode` 时保留该讨论策略，也可显式设置 `orchestration.mode=manual`。旧任务和直接 API 创建时没有该字段的记录继续原策略，不批量启动历史任务。

模型调度的工作流程是：读取原始目标、用户修订、参与者输出和已有回执，调用受限调度工具安排工作，再持久记录 `continue`、`wait` 或 `deliver` 决策。继续执行不依赖再收到一条用户消息。用户插话改变任务依据；暂停、完成、销毁及普通审批优先于后台模型。

后台模型只可查询当前任务/现场和向当前任务参与者投递。它不能验收、完成、清理、批准菜单、跨任务操作或直接写代码。已有参与者由主入口模型按用户目标选择；本轮未新增后台无限扩充 Agent 的机制。

默认模型调度预算为 32 次决策、240 分钟，可用 `orchestration.maxDecisions`（1–256）和 `maxMinutes`（1–1440）设置。达到预算保留输出和决策、明确报告需要继续处理，不把预算耗尽当作目标完成。手动轮转保留原讨论预算。

最终交付与用户验收分开：`deliver` 选择任务内已采集的真实参与者最终输出，复用该输出原始消息回执，已送达正文不重复推送，未知确认不换消息编号绕过；任务仍等待用户验收；只有明确用户完成操作才进入原有资源收尾。调度决策可由 `task_get.orchestrationHistory` 查询。

## herdr 源码/API 核对

核对仓库为 [herdrdev/herdr](https://github.com/herdrdev/herdr)，提交 `8d95e9bd45338c43091e04ef0c976086bb09163a`，源码元数据版本 0.9.1 / 协议 22。

- `src/app/api/agents.rs`：`agent.prompt` 的 `agent_blocked` 在输入写入前拒绝，应记为明确未执行；它与写入后超时或 stalled 的未知结果不同。
- `src/api/wait.rs`：prompt 的可选等待追踪原生状态变化，并不是业务任务或特定回合完成证明。
- herdr 继续负责 workspace/pane、Agent 启动、输入、状态与关闭。应用持久保存输入意图，观察原生 transcript，并把它转化为调度事件；不替换 herdr 执行层。
- 长 transcript 的输入回读按行读取，不因文件超过原先整体读取阈值而丢失投递证据。
