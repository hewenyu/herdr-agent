# 持久化任务 Leader 与上下文边界

本变更作为一个 PR 交付，不把查询止血与调度重构拆成两个发布版本。发布仍遵循[发布流程](releasing.md)：源码根包版本不是分发版本，合并后由新 tag 生成单一版本；不重标记旧二进制，也不自动操作线上任务。

## 问题与边界

旧实现使用低层 pi Agent，而不是带完整会话持久化与压缩策略的 AgentHarness。`task_get` 将完整工作流、调度历史和不可变决策快照拼入一次工具结果；一个实际只读样本达到约 5.76 MB，其中约 5.47 MB 是决策历史。进度工具也可能一次返回约 200 KB。

这不是普通长对话：最新工具批次受保护、不能作为旧历史丢掉，而压缩入口又位于工具结果已进入上下文之后。超限错误被 pi 转成 assistant error，再由封装降为一般模型失败；恢复复用了同一份超大 checkpoint，未重新建立可发送的模型上下文。

修复必须同时覆盖：

- 数据入口：默认只读状态摘要，完整审计与原文按需读取。
- 模型边界：限制完整序列化结果，而非只截正文或只限制条数。
- 持久化：模型投影与原始结果分开；checkpoint 保存实际缩减后的消息。
- 恢复：先做有界恢复和预算检查，不把同一份超限上下文当网络错误重复提交。
- 调度：每个任务有独立的持久化 Leader，不把任务审计或所有参与者 transcript 塞给面向用户的外层 Agent。

## 数据与权限分层

```text
飞书 / Web 用户交互 Agent
  → 状态、控制、受任务作用域约束的详情工具
  → 每任务独立的持久化 Leader
      → 任务看板、约束 / 证据的按需读取
      → 显式调度工具
      → 修订、依赖、目录、评审与回执门禁
      → herdr 托管的 Claude / Codex
```

沿用现有工作流计划及节点进度作为任务看板，沿用原生执行器、操作回执和已确认输出。v3 工作流不再用一次性 enum 选择替代任务 Leader 的完整工具循环；已冻结的 v2 工作流保留显式兼容路径，不通过改变历史计划协议来强制迁移。程序计算合法动作是执行安全门禁，不是把业务调度策略重新硬编码进程序。

三个数据面不能混用：

| 数据面 | 用途 | 不具备的权力 |
| --- | --- | --- |
| 原始记录、不可变审计、操作回执 | 完整追溯与执行恢复 | 不能因记录体积大而全部进入模型请求 |
| 模型消息、摘要、分页结果、结果引用 | 提供当前决策所需的有限上下文 | 不是新增用户授权，也不证明外部操作已确认 |
| 受限执行器及验证逻辑 | 校验当前修订并执行合法动作 | 不能凭 Leader 最终文字代替验收或交付证据 |

## 模型结果与恢复

业务工具先产生 canonical 结果。成功 / 未执行 / 未知、创建事实及参与者投递证据先按原结果核验，再生成模型投影。投影或原文索引失败不得把已经完成的业务操作改判成未执行。

全局限制是最后防线，不能代替领域摘要：默认进度应保留状态、阻塞、当前节点和交付事实，而不是返回截断的巨大 JSON。详情页需要完整封装的字节预算，单个巨大字段也必须分页；偏移推进按实际返回内容计算。分页和截断必须明确标注，缺页不表示记录不存在。

结果引用只能在可信绑定的所有者、会话及任务作用域内读取，不是任意路径读取器。历史原文仍保存在原始存储中，不通过 `AgentMessage.details` 等隐藏字段绕过模型预算。

分页必须在实际模型消息里无损，不能只保证工具函数返回了完整正文。读取页不应被再次投影成另一层引用，但这项例外须绑定真实读取工具的调用身份；普通业务结果即使含有 `reference` 或完整分页字段，也不能仅凭数据形状绕过原文持久化。旧的 12 KiB 存储页保留页号，必要时使用页内偏移分段读取，不静默重排历史页。

关键预算与语义：

- 单个模型工具结果的上限是 **16,384 字节**，需要计算最终消息的完整 JSON，包括工具名、调用 ID、错误标记以及正文作为 JSON 字符串再次转义的开销。这个约束同样适用于旧 checkpoint，不能只保护新执行的工具。
- 完整请求预算同时计入 system、所有工具定义、消息、1,024 token 固定开销及 4,096 token 输出预留。不能把每个工具结果都有界误当成整个请求一定有界。
- Leader 激活的 inline 目标是 **12,288 字节**。超过该值不是截断许可：完整当前请求可单独作为持久化 user 消息，短 prompt 仅指向它；连完整必需输入也容纳不下时，必须在推理前以 typed budget 错误拒绝。
- 当前硬约束必须完整进入本轮上下文，或通过有作用域、可读完且由程序核验**模型实际收到全部内容**的读取流程提供。工具执行过不等于内容已进入模型请求；同批次的读取与写入不能绕过此门禁。仅写“已截断”或“请自行查询”，不能允许模型在未获得完整约束时提交动作。
- 原始工具结果先持久化，再提供有界引用和详情页；摘要、预览或分页不改变原始执行结果，也不让失败变成成功。

恢复先核对写操作账本：

1. 已完成：使用已保存的真实结果，不再次调用写工具。
2. 明确未执行：按现有恢复规则处理。
3. pending / 未知：停在核验边界，不根据模型推测重试。

typed `context_budget` 应保持上下文错误身份。不能仅凭可变的初始历史、已有引用或任意两个 checkpoint 的差异就重试。缩减证明须在保存时产生，并与当前持久 checkpoint 的摘要匹配；后续保存覆盖 checkpoint 时，旧证明失效。也可依据本轮精确的已完成回执修复，再对恢复后的完整请求检查预算。

此处 checkpoint 是保存时证明的身份锚点，不冒充 provider 实际失败请求的完整快照。没有有效缩减或精确修复证据就不进行预算重试。用户输入或工具定义本身不可安全缩减时应明确停止，不能为塞进模型而偷偷丢掉硬约束。

checkpoint 裁剪以完整的工具调用 / 结果批次为单位，字节数包括消息数组、分隔符和新增摘要。当前完整强制要求不能被消息条数上限挤掉。尤其是 `resume: true` 时，pi 使用恢复消息而非重新消费 `input.prompt`；因此仅把要求留在新的 prompt 或未读取的指针里，并不能保证恢复后仍遵守要求。

## Leader 与存量兼容

- 独立任务使用独立 Leader 上下文；不继承用户外层会话或其他任务 transcript。
- 同一任务的后续事件沿用其上下文，但新的用户修订始终高于旧计划和旧摘要。
- 事件先持久化，再执行；稳定事件 ID、执行账本及任务锁共同约束恢复与重复唤醒。
- 节点 ready 或执行器 inactive 只表示当前状态，不自动等同于已派工、已交付或任务完成。
- 调度工具不能完成 / 关闭用户任务，不能自行扩大授权目录、跳过独立评审、伪造确认回执。
- 已冻结的旧计划、决策和已发送操作继续由原执行协议核对，不批量重放历史事件，不修改不可变审计。
- 暂存计划不等于已获授权。冷恢复须重建已完成的选择及其独立授权结果，保留授权凭据并验证当前任务 / 事件 / 修订；不得因存在草稿就绕过合同撤销或文档写入授权，也不重复执行已经完成的规划调用。
- 选型先持久化候选，再提交 Leader 完成回执，防止回执提交后的进程退出丢失选择。复用必须同时具备有效候选记录和同一作用域的已完成收件箱；错误或取消前暂存的候选不是完成证明。后续非法 / 重复选择须先持久撤销旧候选，不能在返回时重新写回使其复活。
- 原生回执桥接须匹配真实投递记录、操作指纹、参与者及当前作用域，兼容历史提示协议的实际正文格式。外观相似的成功文字不能解除未知状态；证据不足时保留阻塞，不重发来补证。
- 存量 `model` 任务保留其原参与者输入与交付协议；接入独立 Leader 会话，不同时启动另一套 workflow 调度。新任务仍沿用 workflow 默认值。
- 手动任务和已有 round-robin 兼容路径不自动迁移为新调度模式。

## 与 DSH 参考实现的关系

借鉴的是模型主导的 Leader、持久化事件、任务看板和按需读取的分层。并未将 Cordis 服务搬进 myrix，也未假设低层 pi 自动提供完整 Harness。

DSH 自身也存在 spill 失败时保留原文、子任务结算文本未统一封顶等边界，不能照搬为“永不超限”保证。尤其不能把 65,536 token 的默认 headroom 用在 myrix 的 50,000 token 配置上；预算须适配实际容量，同时计入系统提示、工具定义和输出预留。

## 验收范围

需覆盖正常路径和对抗边界，而不是只更换工具名：

- 至少 6 MB 的工具 / 决策历史；默认查询及每个完整模型结果都有界，原文可追溯。
- 首个工具结果超大、恢复 checkpoint 超大、巨大错误和元数据、多工具同批返回。
- 已完成写操作后投影失败不重发；未知操作不重发；跨所有者 / 会话 / 任务读取拒绝。
- Leader 多次激活与冷恢复、重复事件、用户修订抢占、任务上下文隔离。
- 独立评审、授权来源、目录占用、报告合同、原生投递回执、用户验收 / 关闭规则不退化。
- 现有测试、类型检查、lint、行数限制和构建；本地验证不冒充真实飞书 / 模型线上验收。

最终 PR 说明记录实际执行的验证命令与结果。线上配置、运行中的服务、已有任务状态和不确定操作均不在本次自动修改范围内。
