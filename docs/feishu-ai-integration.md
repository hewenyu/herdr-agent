# 在飞书中用自然语言管理 herdr 任务

更新日期：2026-09-17。

本项目的 AI 入口基于 [Eino](ai-framework.md)，运行在 Go 服务中，使用用户配置的模型 API、模型名称和 API key。在现有飞书应用机器人的私聊里直接描述需求，即可查询项目、创建开发任务和主动查询任务总览。例如：“在 herdr-agent 项目里排查登录失败的问题”“目前有哪些任务正在进行”。补充要求、具体进度和验收结单在对应任务群继续。日常操作不需要记住 `/new` 等命令。

Pi 的相关框架包使用 TypeScript；当前实现采用纯 Go，保留自然语言理解和受控工具调用的能力目标，不依赖 Pi 或 Node.js。个人飞书助手的 MCP 接入是另一条已调研的候选路线，见本文末尾；当前入口使用本项目自己的机器人。

## 调用关系

```text
用户在本项目飞书机器人私聊中描述需求
  → 本项目检查飞书消息发送者的身份与允许名单
  → 配置的模型理解需求，调用本项目提供的任务工具
  → 本项目按操作者身份和项目配置管理 herdr 会话与飞书任务
  → 工具返回实际状态、最近回复和任务链接
  → 模型根据工具结果生成答复，本项目完整保存并转发
```

一个项目可关联多个本地目录，在本机配置页面管理。AI 选择已经配置的项目名称和执行 agent；只有用户明确要求新建项目时才创建目录，不接受任意本地路径、终端窗口或操作者身份作为工具参数。模型负责任务理解、工具选择和答复；本机 Codex 或 Claude 继续负责执行开发任务。

入口私聊用于需求沟通、澄清、创建任务和主动查询总览。提示词要求模型在创建后说明登记结果、提供实际已有的任务/群链接；群尚未就绪时说明稍后提供入口。执行进展、启动确认、审批和验收通知只发到任务群，不在入口重复。启用任务管理后，无关本地 agent 也不会向入口主动推送，即使配置了 `feishu.notify_chat_id`。每个任务群始终绑定一个任务。群内自然语言经受限任务助手处理：进度查询读取当前任务，需求和反馈发送给对应 coding agent，明确验收结单则完成并关闭任务会话。无需 @ 或斜杠命令，启动确认、审批和主动进展也留在群里。群工具不能切换任务或新建项目。模型、记忆或上下文预算失败时，只记录安全的错误类别，不发送固定替代答复。已发生的工具操作仍保存幂等回执，下一轮可由模型查询恢复；失败不会把同一段文字误发给终端或重放操作，用户未见的失败回复也不会变成后续对话中的建议。

应用和任务群的所有自然语言请求都进入模型，包括进度查询和关闭确认；显式 `/` 或 `／` 命令保留原有命令路由。用户明确要求新建项目但未命名时，模型可选择
合理名称并创建；有必要时也可追问。之后只回复“就叫 pelican-bike-svg”仍承接原来的 agent、文件要求和“不用测试”等约束。
已有任务不会自动拦截新的创建请求。模型的非空成功回复完整保存、原样返回；不使用关键词或正则筛选，也不附加旧任务快照。
会话按用户、聊天和任务绑定隔离，重启后可续聊。

启用 AI 时，建群欢迎、入口群链接、进展和关闭前通知均将结构化事件交给模型决定是否发送及发送内容。
通知只提供当前任务的查询工具，不授予任务写操作；不会在生成失败时换成固定文案。完整送达的通知和 agent 最终回复会写入群对话历史。
普通答复生成成功后仍处于待送达状态，发送失败或只送达部分内容不会成为后续可确认的建议。
工具明确返回执行前校验拒绝时，模型可以纠正参数后继续；执行结果未知时保留幂等保护。

本地回归、真实模型与隔离 Codex 检查的运行方式，以及飞书现场验收边界，见[模型回复与投递验证](model-reply-validation.md)。

模型根据上下文选择 `herdr_list` 的 `all` 参数。工具默认只返回未结束任务，`all=true` 可查询已完成和已销毁记录；
服务不根据用户措辞覆盖模型参数，任务归属仍在工具层校验。群工具只操作服务端绑定的任务 ID。

模型通过工具取得实际进度并生成答复，服务不会预先查询任务快照。提示词要求模型区分 agent 自述和已验证事实，
说明首次要求未送达、执行错误、同步中等状态；目录条目只代表当前文件系统现况，不等于该任务已生成并验证产物。
历史 AI 回复原文保留供对话承接，当前事实仍须重新查询工具。

同步飞书任务描述时，Agent 输出中的本地文件链接会转换成包含文件名和路径的普通文字，避免飞书拒绝不支持的 URL；合法的 `http://`、`https://` 和 `applink://` 链接保留。原始 Agent 结果不会因此改写。

## 配置与使用

沿用本项目已经完成授权的飞书应用，无需飞书 CLI，也无需给云端个人助手发布一个可访问本机的 MCP 地址。具体配置字段、API 协议和示例以 [README 的自然语言任务入口](../README.md#control-tasks-with-natural-language)为准。

1. 启用任务管理，确认当前用户在本项目允许名单中。在本机配置页面设置项目名、一个或多个目录及默认 Codex 或 Claude，也可以稍后明确要求 AI 创建新项目。
2. 启用 AI 入口，设置模型服务的协议、API base URL、模型名称及请求超时。选用支持工具调用的模型。
3. 将模型服务的 key 直接写入 `~/.herdr-agent/config.toml` 已有 `[ai]` 段的 `api_key`，然后重启 `herdr-agent serve`。新电脑无需设置模型密钥环境变量或克隆仓库。模型 key 只从 TOML 读取；不再读取环境变量或 `.env` 中的 `HERDR_AGENT_AI_API_KEY`，老用户需将 key 迁移到 TOML。飞书凭据仍使用原有 `setup` / `.env` 流程。配置示例见上述 README；`v0.2.2` 不支持 TOML `api_key`，需使用包含此修改的二进制。
4. 启动时程序自动核对飞书应用权限；如本地页面提示补授权，点击当前链接登录确认，等待程序核验生效后自动继续。
5. 打开本项目机器人的私聊创建任务或查询总览，再进入对应任务群沟通实现细节、询问进度和验收结单。

自然语言消息、相关任务摘要及工具结果会发送到配置的模型服务。任务执行仍使用本机既有的 Codex/Claude 环境；入口模型和实际执行开发的 agent 可分别配置。

## 上下文压缩与记忆存储

在已有 `[ai]` 段设置 `context_tokens = 50000`，或不写该字段使用相同默认值。
这是输入上下文压缩阈值，允许 `16384..1048576`，包括系统指令、对话、工具定义和本轮工具结果。
程序按 UTF-8/JSON 字节及结构开销保守估算 tokens；达到阈值时使用 Eino 的原生摘要机制压缩旧上下文，
保留近期问答与当前输入。模型输出单独预留 `4096` tokens，选择阈值时应保证模型实际窗口容纳输入和输出。
不再以固定 40 条消息为界静默删除更早的问答。

压缩会保留已确认要求、否定约束和待回答的问题。摘要只是历史记忆，不能成为新的用户授权或当前进度证据；
状态查询仍读取实际任务和本轮工具结果。压缩调用不提供任务操作工具。模型明确标记为不完整或截断的输出会被拒绝；压缩失败时保留原对话并记录错误类别，
超长输入或工具结果仍受请求预算保护；已取得的操作回执保留，不自动重复执行工具。

`[memory]` 控制摘要存储和召回，独立于 `[ai]` 的模型、协议和密钥。默认 `provider = "file"`，
在 `~/.herdr-agent/memory/` 下保存按用户、聊天、任务隔离的摘要。配置 `provider = "http"` 时，
服务需要实现通用、按 scope 隔离的 Recall/Store/Forget 协议；它不是 Responses 或 Messages 模型端点。
可在 `[memory.users."ou_..."]` 为指定用户配置独立 provider，其地址、key 和超时不继承全局配置。
未配置覆盖的用户使用全局 provider。所有记忆 API key 仅从 TOML 读取。

本地 `conversations/` 仍保存近期问答原文、摘要检查点与消息回执，压缩移出的原文保存在其 `archive/` 下；
`assistant-operations.json` 仍保存工具操作回执，这些内容不会随 HTTP provider 配置迁移到远端。
provider 故障不会自动切换存储或清空历史。切换 provider 后，下一轮使用记忆的对话会将本地检查点中的摘要同步到
新存储；旧服务的数据和问答原文不会自动迁移或删除。外部服务需实现本项目的 HTTP 协议。
完整配置、HTTP 协议、隔离范围和恢复方式见[对话与记忆说明](conversation-memory.md)。

## 启动权限检查与补授权

每次 `herdr-agent serve` 都先取得单实例锁，再用新获取的应用 token 通过
`GET /application/v6/scopes` 只读查询当前 App ID 已授予的权限。检查覆盖基本聊天权限，以及启用
`tasks.enabled` 后的任务、建群、解散群和群消息权限。该查询不要求额外申请权限，通过后才建立飞书
长连接并处理任务。检查 scope 不代表已验证事件订阅、卡片回调或应用可用范围。

已有应用缺少权限、App Secret 缺失或失效时，程序为同一个 App ID 生成飞书登录补授权链接；用户登录
确认后，刷新凭据写回本地，白名单和项目配置保留。程序再次查询权限，只有所需 scope 生效才继续启动。
这个流程不会新建应用或额外开启飞书长连接，也不需要飞书 CLI。

等待期间本地页面（默认 **http://127.0.0.1:18790/**）仍可用，顶部展示授权状态、缺少的权限、
可点击的当前登录链接。程序自动打开该页面一次，启动日志也打印授权 URL。使用 `--no-config-ui` 时，
程序尝试直接打开授权页，也可以复制日志链接到浏览器。过期链接会在重新核验权限后自动更新；网络或服务错误单独
显示并重试，不会将未知状态当成权限不足。

飞书返回的官方登录链接可能位于 `https://open.feishu.cn/page/launcher`。启动授权和本地页面
使用同一套 URL 校验规则，允许受信任的官方 HTTPS 地址，并拒绝伪造子域、带用户信息的地址和
非标准端口。尚未发出链接时失败会明确提示生成失败，已有链接后授权未完成则提示自动换新链接。
错误提示不包含远端原始响应或凭据。

初次安装没有有效 App ID 或白名单时，仍需运行 `herdr-agent setup`。手动维护可使用
`herdr-agent setup --update-permissions`，运行这个独立命令前需要停桥；正常 `serve` 启动补授权期间
不需要另开 setup，确认后也无需重启。若租户需要审批或发布，按飞书页面要求完成，再等待启动检查通过。

## 本地项目配置

`herdr-agent serve` 默认同时提供 **http://127.0.0.1:18790/**，前端页面和 API 都由 Go 服务提供。
尚未启动桥时可运行 `herdr-agent configure --open` 单独打开页面；它与 `serve` 共用实例锁。
桥已运行时直接打开现有页面。需要持久修改地址时，在 `~/.herdr-agent/config.toml` 已有的 `[ui]` 段中设置：

```toml
[ui]
config_listen = "127.0.0.1:18791"
```

`serve` 和 `configure` 都读取这个配置，默认值为 `127.0.0.1:18790`。各自的
`serve --config-listen 127.0.0.1:18792`、`configure --listen 127.0.0.1:18792` 参数优先于 TOML。
地址只允许使用 loopback IP；修改 TOML 中的地址后，需要重启正在运行的命令。
端口冲突时，改为可用端口，或使用 `serve --no-config-ui` 关闭页面，从日志获取授权链接。

页面支持一个项目配置多个文件夹、选择默认项目和 agent。第一个目录作为 agent 工作目录，其余目录通过
`--add-dir` 传入。保存或启动时主目录自动初始化 Git，已有有效仓库和 worktree 保留；附加目录不要求 Git。
本机需安装 Git。目录不存在时不能保存或启动新任务。已配置目录被移走
不会阻止页面启动，可在页面修复路径。已有任务保留创建时的目录快照，修改后的项目配置立即用于新任务。

全局 Bypass 开关默认开启，新 agent 分别使用 Codex 的 `--dangerously-bypass-approvals-and-sandbox`
或 Claude 的 `--dangerously-skip-permissions`，跳过常规执行审批。关闭后，新 agent 使用正常权限处理。
运行中的任务保留原模式。首次保存目录配置前可在 TOML 设置 `tasks.bypass = false`，后续页面保存优先。

首次保存后，完整项目列表、默认项目和 Bypass 开关写入 `~/.herdr-agent/projects.json`，文件权限 0600。
这个文件是后续项目配置来源，TOML 项目表只负责初始导入；`tasks.enabled` 与轮询间隔仍由 TOML 控制。
项目变更不需要重启。页面不编辑模型 API key；模型配置和密钥均在 TOML 的 `[ai]` 段维护，修改后重启服务。

“在已有项目里新建任务”只使用配置目录。“新建一个 demo-api 项目，实现健康检查接口”才允许 AI 通过
`herdr_create` 的 `new_project=true` 显式创建 `~/herder-agent-code/demo-api/`，并登记为可复用项目。
这里的 `~` 属于运行 Go 程序的操作系统用户，不按飞书用户另建 home。主目录自动执行 `git init`，
不自动提交或创建 worktree；同名目录已存在时拒绝接管。删除项目配置保留目录和已有任务。

## 如何验证

启动 `herdr-agent serve` 后，先查看本地页面的飞书授权状态：权限齐全应直接通过并连接；需要补授权时，
点击当前链接登录确认，权限生效后应自动继续。授权等待期间页面应可访问，已有白名单和项目配置保留。
网络检查失败应显示未确认并重试；链接过期应换成新链接。

权限就绪后，在机器人私聊发送只读请求：

> 看看可以操作哪些项目，再告诉我现在有哪些任务在进行。

模型回复应依据本项目配置中的项目和当前用户的工具查询结果。工具调用失败或没有任务时，由模型决定如何说明，不能将聊天记忆或示例数据当成实时结果。模型不可达时只记录错误类别，不发送替代任务回复。

查询通过后，再发送：

> 在 herdr-agent 项目创建一个测试任务，让 Codex 不修改任何文件，只回复 FEISHU_AI_OK。

检查以下结果：

- 入口收到简短创建回执和实际任务/群链接，不包含目录、执行进度或审批详情；群未就绪时说明稍后提供入口。
- 明确新建项目后，模型可以自行选名执行；必要澄清由模型发起。只补充项目名或 agent 后，仍承接最初的完整要求。普通问候和需求讨论不应被替换成任务列表。
- 先创建鹈鹕动画，再明确创建宇宙飞船动画，得到两个独立项目和任务；第二次请求不被第一个任务的状态替代。
- 模型成功回复原样保留，失败只在日志记录错误类别，不生成旧任务快照或固定兜底答复。
- 飞书任务与独立任务群已创建，任务链接可以打开；后续执行进展、审批卡片和验收通知只在群内出现。
- 在入口查询任务时，由模型调用 `herdr_list` 并总结实际返回的数据；核对 `all` 参数保留模型选择，工具只返回当前用户有权访问的任务，已销毁记录的状态为已关闭。
- 本机 herdr 创建了对应会话，agent 执行了测试要求，回复写回飞书。
- 在任务群直接问“现在任务进度如何”，得到当前绑定任务的实际阶段、目录现况、最近回复和更新时间。
- 直接在任务群补充要求，消息到达该任务绑定的 agent。
- agent 一轮回复结束后显示待验收或等待下一步；明确完成操作才标记飞书任务完成。
- 在飞书任务面板勾选完成，也会保存结果、关闭对应 Agent 和执行窗口并自动解散任务群。关闭通知后的宽限期内在面板重开，会取消关闭；清理失败自动重试。
- 在任务群发 `/关闭项目`，第一条只显示说明；回复“确认关闭”后，飞书完成状态得到确认、结果保存、群内收到关闭通知，再关闭对应 Agent 和执行窗口、自动解散群；代码与项目配置保留。
- `/help`、`/tasks` 和新群欢迎消息均列出关闭入口。显式斜杠命令使用命令路由，`/task close` 可直接登记验收结单；启用 AI 后，“确认关闭”等自然语言交给模型理解并调用当前任务的工具。
- 说“没有验收，不要关闭”不应触发关闭。明确“只标记完成，保留群”或使用 `/task complete` 时会话继续保留。
- Codex 首次目录信任卡片的 Yes 根据当前选中项执行原生确认；No 和其他菜单不追加 Enter。旧卡片已使用时，在任务群发 `/screen` 获取新卡片后再操作。

长对话还需验证：重启后短回答能够续接、达到配置阈值后仍记得原始约束、摘要中的否定条件不会变成结单授权、
不同用户与不同任务群不会读到彼此的记忆。模拟摘要或存储服务失败时，原有对话和操作回执应保留，
同一条飞书消息重送不应重复创建任务。这些自动化检查使用临时目录和本地 HTTP 替身，现场验收需另外核对。

创建和销毁会产生真实资源变化，使用单独测试任务核对。只通过本地测试不能算作模型 API、飞书应用与本机 agent 的端到端验证通过。

## 调研背景：个人飞书助手与 MCP

飞书[专属工作伙伴说明](https://aily.feishu.cn/hc/1u7kleqg/jsmwydi4)介绍了可自定义名字和技能的个人 AI 助手；[更名说明](https://www.feishu.cn/hc/zh-CN/articles/790732948604)注明飞书 aily 于 2026 年 8 月 14 日更名为“豆包工作伙伴”。仅凭联系人显示名称，不能确定账号当前可用的产品能力。

官方[添加和使用 MCP](https://aily.feishu.cn/hc/1u7kleqg/fiogabrc)文档说明个人助手和自定义智能体可以添加 MCP，支持 SSE、Streamable HTTP、自定义请求头及个人可用范围；[技能说明](https://aily.feishu.cn/hc/1u7kleqg/zja0qy5v)还描述了上传技能文件的能力。云端助手要操作本机，需要可达的服务和身份验证；上传一份技能说明不会自动获得本机访问能力。

[企业工作伙伴 MCP 说明](https://aily.feishu.cn/hc/1u7kleqg/73ahi33a)提供可选用户身份签名，但不能据此认定个人助手界面也支持同样配置。本次未直接核验用户个人助手的管理页，也没有验证个人助手到本项目的 MCP 链路；它不是当前机器人 AI 入口的配置前提。

飞书另有原生任务智能体注册、主页更新和执行步骤写入接口，可在[官方公开 schema](https://github.com/larksuite/cli/blob/main/internal/registry/catalog/services/task.json)核对。这些接口描述智能体登记与执行记录，本身不证明个人助手会自动发现或调用本项目，也不替代任务执行入口。
